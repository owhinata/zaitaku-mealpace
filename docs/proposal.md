## 1. 背景

家庭で経口摂取を続ける嚥下障害の人には、専門職が見ていない毎日の食事を記録する手段がない。本企画は、その空白を家庭用の非侵襲センサで埋める装置を作る。

嚥下障害は、食べ物や飲み物を口から胃へ安全に送り込む機能の障害である。主な原因は脳卒中、神経変性疾患、加齢による筋力低下で、最大のリスクは誤嚥と、それに続く誤嚥性肺炎である。むせを伴わない不顕性誤嚥は本人も介助者も気づけない。神経疾患による嚥下障害では、客観的評価で見つかる割合に対して本人の自覚が低いこと、症状が日内で変動すること、嚥下の開始そのものが遅れることが報告されている。

本企画の直接の対象は、在宅で家族介助のもと食事をしている、神経疾患による嚥下障害と片麻痺を持つ家族一人である。ただし装置の設計は特定の疾患に依存せず、在宅で経口摂取を続けるすべての嚥下障害の人と介助者に広げられる。

## 2. 嚥下評価とは

嚥下評価の目的は「安全に口から食べられるか」「どの食形態・姿勢・一口量なら安全か」「訓練で改善しているか」「悪化していないか」を判断することにある。方法は4層に分かれ、精密になるほど侵襲と頻度の制約が増える。

| 層 | 方法 | 何を見るか | 実施者・場所 | 侵襲 | 頻度 |
|---|---|---|---|---|---|
| 問診・質問紙 | EAT-10、聖隷式嚥下質問紙 | 自覚症状 | 誰でも | なし | 随時 |
| スクリーニング | RSST、MWST、フードテスト、頸部聴診 | 空嚥下回数、むせ・声の変化・嚥下音 | 看護師・ST・歯科衛生士 | ほぼなし | 週〜月 |
| 精密検査 | VE、VF | 咽頭残留、喉頭侵入、誤嚥 | 医師・歯科医師 | あり | 年数回以下 |
| 機器計測 | 嚥下音・喉頭運動センサ、舌圧計、表面筋電図 | 嚥下の発生・タイミング・回数、喉頭挙上 | 専門職のセッション | なし | セッション単位 |

VEは咽頭を直接見られる唯一の実用的な手段で、誤嚥の確定と食形態の決定には欠かせない。ただし鼻からスコープを入れるため異物感と緊張を伴い、検査室の姿勢で検査食を数口飲み込む10分程度を切り取るしかない。本企画は4層目の機器計測を家庭の食卓に持ち込み、上位3層では構造的に取れない「毎食・日常環境・連続」の記録を作る。

## 3. 現状の課題

年1回程度のVEと次のVEの間に、嚥下の状態を知る手段が介助者の目視しかない。

- **観察の空白。** VEは「必要があれば予約」の体制で年1回程度。次の検査までの約12か月、状態が変わっても気づく仕組みがない。
- **検査環境と日常の乖離。** 日常の食事はいつもの車椅子かベッドで30分かけて行われ、日によって調子が大きく違う。検査当日が良い日なら、その結果は日常を代表しない。
- **介助者の観察が主観に留まる。** 「角度が保てても飲み込めない日がある」「同じ時間帯でも良い日と悪い日がある」という観察は正確だが数値化されておらず、「いつから、どう変わったか」を伝えられない。
- **姿勢と嚥下の関係が分からない。** 毎食クッションで姿勢を手動調整し、ベッドでは約36度が食べやすいと分かっている。しかし角度と嚥下の関係は、両方を同時に記録した人がいないため誰にも分からない。
- **服薬との関係が分からない。** 食事時刻・服薬時刻・嚥下の状態を重ねて見た記録がない。

専門職は年に数時間しか見られず、家族は毎日見ているが記録する道具を持たない。

## 4. 解決したいこと／しないこと

本装置は誤嚥を検出するものではなく、毎食の嚥下を記録して介助者と専門職の判断を支えるものである。

**解決したいこと**
1. 毎食の記録：一口ごとに、嚥下までの時間、回数、喉頭の動き、直後のむせを自動記録する。
2. その場のペーシング支援：嚥下の状態を食事中に介助者へ光で返し、「次の一口へ進んでよいか」の目安を数値で裏付ける。
3. 経時変化の可視化：食事ごとの要約を蓄積し、週・月の傾きを見せる。次のVEを前倒しする根拠にする。
4. 姿勢・服薬との関係の記録：頭部・体幹角、場所、服薬時刻を同じタイムラインに載せる。

**解決しないこと**
- 誤嚥の検出・診断。咽頭残留や不顕性誤嚥は外から見えない。それはVEの仕事である。
- 食形態や姿勢の医学的判断。装置は数値を示すだけで、指示は出さない。
- 自動制御。ベッドや車椅子の角度を装置が動かすことはしない。

「VEに代わる装置」ではなく「VEの空白を埋める装置」と表現する。

## 5. 提案する装置

喉元に当てた小型センサで嚥下音と喉頭の動きを取り、その場で介助者にLEDで返し、食事ごとの要約を蓄積する。処理は装置内で完結し、音声も映像も外に出さない。

| 項目 | センサ | 一口ごとの指標 |
|---|---|---|
| 嚥下イベント | 頸部の加速度（IMU）＋嚥下音（マイク） | 発生の有無、発生時刻 |
| 嚥下開始までの潜時 | 上記＋介助者の一口ボタン | 口に入れてから嚥下までの秒数 |
| 嚥下回数 | 上記 | 一口あたりの嚥下回数 |
| 喉頭挙上の大きさ | 加速度・角速度の振幅 | 相対値 |
| むせ・咳・咳払い | マイク | 嚥下直後の発生有無 |
| 頭部前屈角・体幹角 | 頭部IMU、体幹IMU | 初期姿勢と食事中の崩れ |
| 食事場所 | 体幹角から自動判別 | 車椅子／ベッド |
| 服薬時刻 | 手入力（唯一の手入力） | 食事開始との時間差 |

**出力**：食事中はLED3色（緑＝嚥下を確認、黄＝未確認・待つ、赤＝むせ・未嚥下が続く・中断を検討。判定ではなく目安）。食事後は要約。週・月は推移。

**利用の流れ**：食事前に装着・姿勢調整・服薬時刻入力 → 食事中は一口ごとにボタン、LEDを見て次の一口を決める → 食事後は要約が自動保存。

**データの扱い**：生の音声波形は特徴量に変換後に破棄し、保存するのは嚥下イベントの時刻と指標のみ。食卓の会話を録音・保存しない。

## 6. 既存製品・研究との比較

| 製品 | センサ／処理 | 入手性・価格 | 薬機法・場面 | 姿勢の同時記録 |
|---|---|---|---|---|
| GOKURI（PLIMES） | 圧電コンタクトマイク＋IMU／クラウド | 施設限定、個人不可／初期約30万円＋月額約6千円 | 管理医療機器クラスII／評価・見守り | 頸部姿勢のみ |
| B4S（バンドー化学） | 伸縮ひずみセンサ／ローカル | 歯科・介護向け業販／約26万円 | 医療機器ではない／訓練 | なし |
| ノドミル（追坂電子） | 距離センサアレイ | 販売休止 | 研究 | なし |
| 貼付型（米国、研究段階） | sEMG／メカノアコースティック | 臨床試験段階 | 未承認 | なし |
| **本企画** | 加速度＋マイク／エッジ完結 | 自作・本人所有／部品代 | 医療機器ではない／家庭の毎食 | あり |

家庭で毎食使い、介助者にその場で返し、姿勢と同時に記録するものは見当たらない。研究面では、頸部聴診と加速度による嚥下検出は深層学習で検出精度95%超の報告があり、嚥下音と加速度の併用が単独より感度で優れる。方式の妥当性は検証済みで、本企画が検証するのは「安価なセンサと小さなマイコンで、家庭の食卓で同じことができるか」である。

## 7. ハードウェア選定

手持ちの Arduino Nano RP2040 Connect で開始する。マイク（PDM）とIMU（LSM6DSOX）を基板上に持ち、純正製品の条件を満たす。基板そのものを喉元に当てれば追加部品なしで方式の可否を判定できる。RP2040にFPUがない点はint8量子化で回避し、不足なら Nano 33 BLE Sense Rev2 へ移行する。UNO Qは応募時点では使わず、1st Stage通過で供与を受けて Final Stage の「発展性」に充てる。代替センサ（圧電コンタクトマイク、ピエゾ電線センサ）は docs/decisions/0002 参照。

## 8. 技術構成

IMU 104 Hz、マイク 16 kHz。1秒窓・0.25秒ホップで、IMU（振幅、RMS、ピーク数、主軸方向）と音（MFCC、スペクトル重心、ゼロ交差率）を結合して1つの分類器に入れる。第1段階は Edge Impulse で嚥下／非嚥下の2クラス、int8量子化して Nano に配置。第2段階は本人データで再学習し、最初の数日分でその人専用に調整される設計にする。第3段階（UNO Q）は Linux 側でむせ分類と再学習、MCU 側でリアルタイム判定に分担する。記録は時刻と指標のみ。詳細は docs/data-schema.md、docs/evaluation.md。

## 9. 検証計画とスケジュール

docs/plan.md を正とする。9/27 の分岐点で方式の可否を判定し、成立すれば 11月中旬までに実データを伴う動作デモまで到達する。11月時点で「可能性の証明」と言える状態は、開発者自身の体で検出が動いている（動画）、本人の実際の食事で信号が取れている（数食分）、本人データから目視では分からなかった関係が1つ見えている（図）、何が未検証かを明記している、の4点。製品としての完成は求めない。

## 10. 倫理・安全・法規

本装置は医療機器ではなく、診断・治療を目的としない記録・可視化の装置である。「嚥下の状態を記録・可視化する装置」として設計し、誤嚥の検出、疾患の診断、治療効果の判定を目的とした表現を使わない。本人に目的と記録範囲を説明し、同意を得てから装着する。嫌がれば直ちに外す。LEDが本人を急かす道具にならないよう、表示は介助者側に向ける。公開物に本人の顔・声・氏名を出さない。首を圧迫しない伸縮バンド、絶縁ケース、電源は5V以下。本装置は専門職の評価を代替しない。

## 11. コンテスト審査基準への対応

| 基準 | 本企画の答え |
|---|---|
| 将来性 | 専門職が年に数時間しか見られない領域を、家庭のセンサとエッジAIが毎日埋める。「観察の空白」は姿勢・歩行・服薬にも同じ構造がある |
| 独創性 | 家庭で毎食、介助者にその場で返し、姿勢と同時記録する嚥下装置は既存製品にない。当事者の困りごとから出発し、却下した案とその理由まで書ける |
| 完成度 | 開発者自身の動作デモ、本人の実食事データ、そこから見えた関係の図、未検証事項の明示 |
| 発展性（Final） | Linux側でむせ分類と個人再学習、MCU側でリアルタイム判定というデュアルブレインの分担 |

応募条件は「AIスキルの実装および／またはアクチュエータ制御」であり、本装置の作用（LEDによる介助者への提示）は要件上問題ない。自動制御を入れないのは4章の設計判断。

## 12. リスクと対策

| リスク | 対策 |
|---|---|
| 基板マイク・IMUで嚥下が分離できない | 圧電コンタクトマイクを追加。不可なら計画を止める。9/27に判定 |
| RP2040でリアルタイム推論が回らない | int8量子化、窓長短縮。不足なら Nano 33 BLE Sense Rev2 |
| 本人が装着を受け入れない | 眼鏡のつるに頭部IMU。不可なら開発者データのみで応募し、未検証と明記 |
| 食卓の会話・食器音で誤検出 | IMUとの併用。食器音は非嚥下クラスに含めて学習 |
| 本人の体調で試用の機会が取れない | 2〜3食でも「信号が取れた」ことは示せる |
| 一口ボタンが介助の負担になる | ボタンなしでも検出と回数は取れる設計にし、潜時だけをボタン依存にする |
| 「誤嚥検出」と誤解される表現 | 全成果物で表現を徹底。装置の表示にも「目安」と明記 |
