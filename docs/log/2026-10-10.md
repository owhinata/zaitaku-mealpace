## #38 構成 B の取りこぼしの規則（#37 の構成 B の記録の前に固定）

人が 10/10 に決めた。plan #38 第 4.2 節の規則に、閾値 `ZERO_RUN_MS` = 100 ms を入れたもの。**#37 の構成 B の記録を見る前に固定し、結果を見てから緩めない**（0030 決定 5）。

- **0 の区間**: L と R が**両方ちょうど 0** のフレームが **100 ms（48 kHz で 4,800 フレーム）以上**続く区間。`tools/throat_check.py` が回数・合計の ms・最長・位置（秒）を出す。
  - 記録の**先頭**（フレーム 0 から始まる）の区間は「先頭の 0」として別に出し、回数に入れない。末尾の区間は回数に入れる。
  - 100 ms 未満の 0 の連続の最長も参考に出す。
- **使わない目安**（録り直す）。iface が `sh12jk-nz210c-a2dp-unoq` のときだけ当てる:
  1. 0 の区間（先頭を除く）が 1 回以上。
  2. `throat.stop` が `stall`（受信が 2 秒止まった）。
  3. `throat.pipewire.link_check` が `ok` でない。
- 10/7 の 3 つの目安（overrun の行 > 0 は構成 B では `null` で当たらない、`|推定差|` > 125 ms、段差 50 ms 超）と叩きの規則は、構成 B にもそのまま当てる（数字は変えない）。
- `alsa` の iface（有線など）では 0 の区間を数えて表示するだけで、使わない目安に入れない（10/7 の規則と 10/8 の有線の 5 本の扱いは変えない）。
- 根拠（E3、静かにしたまま 60 秒、1 回）: 自然な信号の中の「両方 0」の連続の最長は 3 フレーム（0.06 ms）。先頭以外で 1 ms を超えた区間は 1 回だけで 63.8 ms（12.2 秒目。前後の振幅に変化なし）。
  100 ms はこの 63.8 ms の途切れ 1 回を許し、10/8 に見えた 3 秒級の 0 は拾う。仮の値（10 ms）なら 63.8 ms で毎回当たっていた。
- 0 の区間が「静かにしている間にだけ」出る挙動かは、60 秒 1 回では分からない（63.8 ms は静かな区間の真ん中）。構成 B の `quiet` が毎回この目安に当たるようなら、
  規則を緩めずに止まり、構成 B を `quiet` の基準に使えるかを人に渡す（plan 第 4.2 節）。
- 合成の確かめ（k8。**合成**。48 kHz・2 ch、雑音 RMS 約 60 LSB に、ちょうど 0 の区間を 5 ms・25 ms・64 ms・3 s、先頭に 200 ms、L だけ 0 の区間を 150 ms 入れた）:
  100 ms 以上の区間は 1 回（3 s、10.0 秒目）、合計 3000 ms、最長 3000 ms。先頭の 0 は 200 ms で回数に入らない。L だけ 0 の区間は数えない。100 ms 未満の最長 64.00 ms。
  構成 B の iface では使わない目安に当たり、有線の iface では当たらない。

## plan の見込みと違った点とその扱い（plan #38 は直していない）

1. bluez のノードの `media.class` が `Stream/Output/Audio`（plan 第 3.3 節は `Audio/Source` を求めていた）。→ 起動前の検査と自動で探す条件を「`media.class` が `Stream/Output/Audio` か `Audio/Source`」かつ
   `api.bluez5.profile` = `a2dp-source` に直す。テストは実物の形に合わせ、`Audio/Source` も受けることを 1 件で確かめる。
2. `90-bluez-no-seat.conf` は入れ子の 5 行（plan は 1 行の形を見込んでいた）。→ 中身の検査を、コメント行と空行を除き空白を正規化した上で、期待する 5 行と一致するかを確かめる形にする（1 行の正規表現は使わない）。
3. ノードの形式のレートは 44100。→ `throat.pipewire.node_rate_hz` には 44100 が入る（`pw-record --rate 48000` は PipeWire の変換）。SBC の符号化のレート（`codec_rate_hz`）は確かめていないので `null` と理由のまま。
4. E6 では子がすぐ終わる（起動待ちのタイムアウトではなく `child-exit` の経路。安全側）。→ E7 (b) の「起動待ちのタイムアウト (b)」は架空のノードでは 10 秒より前に子が終わるので、
   実在のノードに対して子と同じ argv を起動し、10 秒後にプロセスグループへ SIGTERM を送る形に変える。
5. ssh のセッションが無いと約 10 秒で arduino の PipeWire が止まり、送信機の A2DP が切れる（`Linger=no`）。→ linger を有効にする（人が決定、メインが `loginctl enable-linger arduino` を実行）。`docs/unoq-setup.md` の設定の表に足した。
6. `pw-record` の起動で WirePlumber が `~/.local/state/wireplumber/stream-properties` を書く（音声ではない状態ファイル）。→ 音声のファイルの確認から除く（`docs/unoq-setup.md`）。
