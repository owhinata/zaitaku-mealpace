## #36 判定の条件（#37 の記録の前に固定）

Issue #36。plan #36 第 9 節による。数字は docs/status.md「判定の条件」と Issue #36 の本文のまま（人が決定、10/3）。#37 の記録を見た後に変えない。
結果を見てから足す集計は「規則の外」と明記する（#35 と同じ）。

### 信号が見えること（3 つとも満たす。経路ごとに判定する）

1. `s` の振幅の比の中央値が 2 以上。
2. `s` の振幅の比の四分位範囲が、`quiet` の四分位範囲と重ならない（`s` の第 1 四分位 > `quiet` の第 3 四分位、または `s` の第 3 四分位 < `quiet` の第 1 四分位）。
3. 6 回の `s` のうち 5 回以上で、マーカーの後 1.5 秒以内 `(t, t + 1.5 s]` に、包絡が静止の中央値の 2 倍を超える。

- `c`・`n`・`t` との違いは数字を並べるだけにする（条件にしない。分けられるかは #40）。

### 経路の差

- 有線（`sh12jk-wired-unoq-usbaudio`）と NZ-210C 経由（`sh12jk-nz210c-rx-unoq-usbaudio`）で、
  `|s の比の中央値（NZ） − s の比の中央値（有線）| ÷ s の比の中央値（有線）` ≤ 0.20。
- 振幅の絶対値は経路の間で比べない（入力のゲインが違う）。比だけで比べる。
- 帯域 100〜500 / 500〜1000 / 1000〜2000 / 2000〜4000 Hz のエネルギーの比は経路ごとに並べる（条件にしない）。

### 解釈を固定する 3 点（人が決めた、10/7）

- 条件 3 の「静止の中央値」= 同じ経路の `quiet` のセッションの包絡の中央値（仮のマーカーの `[t − 2 s, t + 2 s]` を合わせた範囲。叩きの前後は除外で落ちる）。
- 条件 3 の分母: 使えた `s` が 6 回ちょうどなら 5 回以上。6 回未満なら「判定できない」と記録し、録り直すかは人。7 回以上なら最初の 6 回（時刻の順）で数える。
- 経路の名前は 0028 の名前（Issue の本文の `sh12jk-wired-pc`・`sh12jk-nz210c-rx-usbaudio` から替わる）。

### 計算の規則（要約。詳細は plan #36 第 4・8 節）

- 入力: `throat.wav` の L（ch0）を float にし、`scipy.signal.resample_poly(x, 1, 3)` で 16 kHz に落とす（`audio_hz` が 48000 でなければ止まる）。単位は LSB（16 bit）のまま。
  R（ch1）は使わず、L と R の相関と RMS の比を添える。
- 時刻の対応（受信の時刻。主）: `throat_chunks.csv` の各読み取りのアンカー `a_k = t_ms_k − 1000 × (e_k + 1) ÷ 48000`（`e_k` はその読み取りの最後のフレーム）を
  10 秒ごとの区間に分け、区間ごとの最小値を区間の中央の時刻に対して直線で当てはめる（最小二乗）。サンプル `i` の時刻 `τ(i) = 1000 × i ÷ 48000 + c0 + s × (1000 × i ÷ 48000)`。
  区間が 2 つ未満（20 秒未満の記録）は全体の最小値を `c0`、`s = 0`。16 kHz のサンプル `j` の時刻は `τ(3j)`。隣り合う区間の最小の差が 50 ms を超えたら「段差」。
- 叩きによる確かめ: L を 16 kHz に落とした包絡（下と同じ 20 ms の移動 RMS。中心はセッション全体の中央値）で、note が `tap` の `o` ごとに探す窓 `[t − 300 ms, t + 300 ms]` の
  最大の点を取る。基準 = `[t − 1.3 s, t − 0.3 s]` の包絡の中央値と MAD、しきい = 中央値 + max(8 × MAD, 5 LSB)。最大の点がしきいを超えていなければ「見つからない」。
  超えていれば、最大の点から前へたどり、しきいを超え続ける最初のサンプルを立ち上がりとする。`Δ = 立ち上がりの時刻 − マーカーの t_ms`。
  判断: 叩きが 3 回以上見つかり `|Δ の中央値|` ≤ 50 ms なら受信の時刻による対応をそのまま使う。外れたら集計の表に印を付け、使うかは人が決める（`Δ` で対応を直さない）。
- 静止の中央値 = 同じ経路の `quiet` のセッションの 16 kHz の値全体の中央値。包絡 = `|x − 静止の中央値|` の 20 ms（320 サンプル）中心の移動 RMS（端は窓の中にある分で平均）。
  MAD は係数なし。
- マーカーごと（`[t − 2 s, t + 2 s]`）: 基準 = `[t − 2 s, t − 1 s]` の包絡の中央値と MAD。**振幅の比** = `[t − 0.5 s, t + 1.5 s]` の包絡の最大 ÷ 基準の中央値。
  **塊の長さ** = 最大の点を含み、包絡が 基準の中央値 + 5 × MAD を超え続ける長さ（切り出しの中で数える。最大の点が超えなければ 0）。
- 除外: 切り出しが記録の最初・最後のサンプルの時刻の外にかかる（端）、切り出しに別のマーカー（ラベルを問わない。`o` を含む）が入る（別のマーカー）。
- 四分位範囲は `numpy.percentile` の既定（線形補間）。
- 対象のラベル: `water` の `s`、`cough` の `c`、`neck` の `n`、`talk` の `t`。
- `quiet` の振幅の比: `quiet` のセッションに、最初のサンプルの時刻 + 2 s から 4 s おきに仮のマーカーを置き、`s` と同じ計算と同じ除外を当てる
  （叩きの `o` と `q` の近くは「別のマーカー」で落ちる）。
- 帯域のエネルギーの比: 16 kHz の値からセッションの平均を引き、`scipy.signal.welch`（hann、1024 点、重なり 512）でパワースペクトルを出す。ラベルごとに使ったマーカーの
  `[t − 0.5 s, t + 1.5 s]` ごとのスペクトルの平均、`quiet` の仮のマーカーの同じ区間の平均。4 つの帯域のパワーの和を 100〜4000 Hz の和で割った割合（4 つの和が 1）。条件にしない。
- 商用電源のノッチ・ハイパスはかけない（#35 と同じ）。

## Issue #36 の本文との違い

Issue の本文は直さず、理由をここと plan #36 第 0 節に書く。

1. **入力の経路**: 本文は「PC のマイク入力を `sounddevice` で録る」。PC はアダプタを認識せず UNO Q は認識する（0028）ので、UNO Q に挿したアダプタから `arecord` の生の PCM を
   ssh で PC に流し、PC の `tools/record.py` が `throat.wav` を書く。`sounddevice` は使わない（依存を足さない）。PC の内蔵の入力を使うときも、同じ仕組みで `arecord` を
   PC 上の子プロセスにする。
2. **ブランチ**: 本文は試用ブランチ `trial/throat-mic`。#28 は 10/4 に判定済み（0027）なので、docs/status.md「試用ブランチの作業は main に入れてよい（#28 の後。0024）」に従い、
   ブランチを切らず main で行う。
3. **`iface` の名前**: 本文の `sh12jk-wired-pc`・`sh12jk-nz210c-rx-usbaudio` に、0028 の `sh12jk-wired-unoq-usbaudio`・`sh12jk-nz210c-rx-unoq-usbaudio`・
   `sh12jk-nz210c-a2dp-unoq` を足す（本文の 2 つと A2DP は予約）。
4. **形式**: 本文は「16 kHz、モノラル」。アダプタのハードウェアは 48 kHz・2 ch 固定（実測）なので、受けたまま 48 kHz・2 ch で書き、解析で 16 kHz・1 ch に落とす
   （本文の「16 kHz で取れなければ 48 kHz で録り、特徴量の計算で 16 kHz に落とす」に当たる）。ALSA の plug の変換を記録に入れず、落とし方をコードに残すため。
   2 ch を残すのは、NZ-210C の受信機の出力が L 側だけに入る経路がありうるため。
