- **構成 B（送信機 NZ-W210C → UNO Q の A2DP シンク）は動いた**（条件: 上の版、Class = 0x240414、lightdm 側の bluez の監視を止め、arduino 側の seat-monitoring を disabled、鍵を消してからエージェント NoInputNoOutput で承認、取り出しは `pw-record` の標準出力）。
- 構成 A（送信機 → 受信機 → USB オーディオ → UNO Q）は今日は試していない（受信機を 3.5 mm の入力へつなぐ変換ケーブルの有無は人）。
- Issue の文面の `arecord` ではなく `pw-record` で取った（bluez のノードは PipeWire にあり、ALSA の PCM としては出ていない）。

### UNO Q に音声のファイルが残っていないことの確認

- 取り出しは `pw-record … -`（標準出力）だけで、ファイルには書いていない。RMS もその場で畳んだ。UNO Q の上で `arecord` は今日のこの試しでは使っていない。
- 確認の方法（読み取りのみ。10/8 にメインが実行）: 試しを始める前の時刻を基準に、ホームと `/tmp` の新しいファイルを列挙する。

  ```
  ssh arduino@<UNO Q> 'find ~ /tmp -xdev -type f -newermt "2026-10-08 11:00" 2>/dev/null'
  ssh arduino@<UNO Q> 'find ~ /tmp -xdev -type f \( -iname "*.wav" -o -iname "*.raw" -o -iname "*.pcm" -o -iname "*.flac" -o -iname "*.sbc" -o -iname "*.mp3" -o -iname "*.ogg" \)'
  ```

- 結果: 新しいファイルは 5 つ。`~/btmon-nz2.txt`（HCI ログ）、`~/.config/wireplumber/wireplumber.conf.d/90-bluez-no-seat.conf`（上の設定）、`~/.bash_history`、
  `~/.local/state/wireplumber/stream-properties`（WirePlumber の音量などの状態。ASCII テキスト）、`/tmp/.X0-lock`。音声の形式のものは無い。音声の拡張子のファイルはホームと `/tmp` に 0 件。
- `/etc` と `/var/lib/lightdm` の設定（上の表）は人が置いたもので、この確認の範囲の外。
