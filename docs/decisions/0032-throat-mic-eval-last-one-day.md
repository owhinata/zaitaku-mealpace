# 0032 咽喉マイク（M3）の評価側を最後の 1 収集日にする（0014 の手順の変更）

日付: 2026-10-12　状態: 採用（人が 10/12 に決定。docs/log/2026-10-12.md「#39 評価側を最後の 1 収集日にする（人の決定）」）

plan #39 ステップ B（Codex の 3 面レビューを通した）による。docs/decisions/0014 の手順のうち、咽喉マイクの評価側の収集日の数だけを変える。
M1（IMU＋PDM）の規則と、`docs/evaluation.md` は変えない。

## 決定

- 咽喉マイク（M3、#40・#41）の評価側は**最後の 1 収集日**のセッション全部。学習側はそれより前の収集日の全部。
  学習 = 収集日 1（2026-10-11、14 本・2 セット）、評価 = 収集日 2（2026-10-12、7 本）。収集日 3 は録らない。
- M1 の規則（最後の 2 収集日、`EVAL_DAYS` = 2）は変えない。
- 実装: `analysis/train_eval.py` に `EVAL_DAYS = 2`（M1。今のまま）と `THROAT_EVAL_DAYS = 1`（咽喉マイク）を定数として固定し、
  `--throat` の有無だけで決まる形にする。`check_collection_days(train, eval_, eval_days=EVAL_DAYS)` に引数を足し、`--throat` のときは
  `THROAT_EVAL_DAYS` を渡す。検査の中身（評価側がちょうど `eval_days` 日、学習側 1 日以上、学習側のどの日も評価側のどの日より前）と、
  M1 のときの止まる文言は変えない。`--eval-min` の意味（評価側の収集日のセッション数）と必須なことも変えない。咽喉マイクでは `--eval-min 7`。
- 評価側の日数を選ぶ CLI の引数（`--eval-days` など）は作らない。0014「理由」の「結果を見てから動かせる箇所を増やさない」による。
- 再現の条件（咽喉マイクの経路）: 0014「再現の条件」に scipy の版を足したもの。`scipy.signal.resample_poly` が採点の経路に入るため。
  `train_eval.py --throat` の報告の実行の条件に scipy の版が出る。

## 理由

- 人（10/12）: ラベルごとの数が M1 の基準を満たしている。`s` は学習側 67 / 評価側 30、`t`+`c`+`n` は 83 / 33、`quiet` は 5.85 / 2.79 分
  （docs/log/2026-10-11.md・2026-10-12.md）。基準は合計 `s` 50、`t`+`c`+`n` 50（各 10 以上）、`quiet` 5 分で、評価側だけ・学習側だけでも `s` 20 以上。
  先へ進みたい。
- 規則の変更は、咽喉マイクの記録に `split.py`・特徴量・分類器を一度も走らせる前、つまり評価側と学習側のどちらの性能の数字も見る前に行う。
  見ているのは、マーカーの数と `tools/throat_check.py` の記録の健全性の値だけ。

## `docs/evaluation.md` との関係（変えない）

- 「学習と評価はセッション単位で分ける」: 変わらない。収集日単位で分け、同じセッションの窓は片側にだけ入る。
- 「評価には 3 セッション以上を使う」: 評価側は 7 セッション。`split.EVAL_MIN_FLOOR` = 3、`evaluate.MIN_SESSIONS` = 3 のまま。
- 「収集日が異なることが望ましい」: **評価側は 1 収集日なので、評価側の中では満たさない**（「望ましい」であって要件ではない）。
  学習側と評価側は収集日（日付）が違う。
- **M3 の数字を M1（評価側 2 収集日）と並べるとき（#40 の log、#41 の判定）は「評価側 1 収集日」を注記する。** `train_eval.py --throat` の
  報告にも「評価側の収集日: 1」を出す。
- 合格線（M1 分岐点 70% / 3 回/分）、窓、数え方は変えない。

## 学習側の交差検証

- 学習側は 1 収集日なので、0014 手順 4 のとおり**1 セッションごと**（14 fold）。0014 の規則のままで、コード（`cv_groups`）は変えない。
- 注意: 同じ日の 2 セットのセッションが互いの学習側に入るので、収集日ごとの交差検証（M1）より楽観側に出うる。
  閾値を学習側の交差検証だけで決める（評価側は使わない）ことは変わらない。

## 選ばなかった案

- **評価側の日数を `--eval-days N` の引数にする**（既定 2、`--throat` で 1）。実行のたびに選べるつまみが増え、同じデータで日数を選び直せる。
- **収集日 3 を録る**（0031 の 10/11 の改訂のとおり評価側 2 収集日にする）。量の基準は既に満たしていて、日数が延びる（人）。
- **同じ日の朝と夜のセットを 2 つの収集日に数える**。10/11 に採らなかった案（0031「選ばなかった案」）。0014 と `train_eval.py` の収集日の
  規則（フォルダ名の日付）を変えることになり、同じ日の体調・声・部屋の条件を学習側と評価側が共有する。この決定では学習側と評価側の日付が違う。

止まる条件、評価側の保護、`--final`、報告の中身、再現の条件）、M1 の経路、「評価側の数字を一度でも見た後は評価側を動かさない」。
