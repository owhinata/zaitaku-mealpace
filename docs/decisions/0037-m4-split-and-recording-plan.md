# 0037 M4（検出器・咽喉マイク版）の学習・評価の分割と、学習用・評価用の `meal` の記録の計画

日付: 2026-10-24　状態: 採用（人が 10/24 に決定。下の「人の決定（10/24）」）

Issue #46（plan #46、Codex の plan レビューを通した plan による）。M4 の数字（#49、#50 の判定）を出すための分割と記録の規則を、
**M4 の記録（学習用 `meal`・評価用 `meal`）を 1 本も録る前**、つまり M4 のどの性能の数字も見る前に固定する。
`docs/evaluation.md` の定義と合格線は変えない。0011 の数え方、0014 のうち評価側の日数以外、0023 の `s` の押し方と捨てる条件の趣旨、
0031 の記録の範囲（`o start` から後）は変えない。

人の決定（10/24）: 日程（学習用 `meal` 10/25〜10/28・締め 10/28、評価用 `meal` 11/1〜11/4・打ち切り 11/4、#49 は 11/5、#50 は 11/7 まで。
10/13 の「学習用 10/18〜10/22、評価用 10/30〜11/2」を改める。学習用が 1 本も録られていなかったため）、評価側の収集日は 2 日以上、

評価用の `meal` の間はマトリクスを自分から見えない向きに置く。

## 前提

- M4 の合格線は M2 と同じ（検出率 85% 以上、誤検出 1 回/分以下。`docs/plan.md`、0024・0027）。測るのは `self` の `meal` の通し記録。
- M3 の分割（0032・0034）は M3 の判定（0036）のためのもので、M3 の数字はすでに出ている（0034 の印 `docs/log/m3-final-40.txt`）。
- 被験者は `self` だけ（`docs/evaluation.md`「M1・M2 の数字は `self` のみ」を M4 にも当てる。`p1` は M4 に入れない。0024・D11）。

## 決定

### 1. 評価側

- 評価側は、**装置（#47 の `detector.py`）で録った `self` の `meal` の通し記録**。
- 評価側の収集日の窓: `M4_EVAL_FROM` = 2026-11-01 〜 `M4_EVAL_TO` = 2026-11-04。フォルダ名の日付（先頭 8 桁）で決める。
- 評価側 = 窓の中で録り、下の 5 の捨てる条件に当たらなかった装置の `meal` の**全部**。後から選んで外さない（0023 と同じ）。
- 本数と日数: **3 セッション以上**（`docs/evaluation.md`）。収集日は **2 日以上**（窓の中の採用分の全部。ちょうど 2 日に限らない）。
  目安は M2 と同じ: 合計 `s` 50 以上、会話なし 1・会話あり 1（0023 の「届かなくても延ばさない」の扱い。届かない条件は「未達」として #49・#50 に渡す）。
- **0014・0032 との関係**: 0014 は「最後の 2 収集日」、0032 は咽喉マイク（M3）で「最後の 1 収集日」に変えた。M4 では評価側と学習側でセッションの種類
  （装置 / PC の記録）が違い、「名前順で後ろから」の規則では分けられないので、**日付の境 `M4_EVAL_FROM` で分ける**。日数は 2 日以上
  （0014 の側。`docs/evaluation.md`「収集日が異なることが望ましい」を評価側の中でも満たす）。打ち切りまでに 1 日しか録れなかったときは、3 セッション以上なら
  合算を出し、「評価側 1 収集日（0037 の 2 日に届かない）」と注記する（0032 と同じ注記。日数は合算を止める条件にしない）。
- 評価側の装置の `detect.csv`・`feat.csv`（FEAT）は、名前と時刻の列（`t_ms`・`window_t_ms`、採否の確かめ）以外を #49 の 1 回の採点まで開かない
  （`positive`・`prob`・`led`・FEAT の値を見ない。0023「採用前に数字は見ない」と 0014「評価側の保護」）。

### 2. 学習側

- 学習側 = 次の全部（`fw` が `pc-throat`、iface `sh12jk-wired-unoq-usbaudio`、日付が `M4_EVAL_FROM` より前）:
  - M3 の 21 本（0034 の `FINAL-TRAIN` 14 本と `FINAL-EVAL` 7 本。**M3 の評価側だった 7 本は M4 では学習側**）。
  - 学習用の `meal` **3 本**（人の決定 10/13。日程は 2026-10-25〜10-28、人の決定 10/24）。PC の記録の経路（`tools/record.py --throat`、0028）で録る。
  - 追加の条件別セッション（10/11 の 7 本の形）: **録らない**（日程。人の決定 10/24）。
- M3 の評価側 7 本を学習に使うこと: M3 の評価側の数字は 0034 の 1 回で出し、M3 は判定済み（0036）。M4 の評価側は新しく録る `meal` で、
  7 本とは日付も種類も違う。7 本を M4 の学習・学習側 CV・構成の選択（#45）に使っても、M4 の評価側が学習に混ざることにはならない。

- 学習側の一覧は、学習用の記録の締め（2026-10-28 の終わり）の後、#45 が構成を 0038 に固定する前に、名前で固定する（下の「機械が読む行」）。

- 学習のラベルは 0014 のまま（`s` の `[t, t + 1.0]` が陽性、境目は使わない、ほかは陰性）。`meal` では押せなかった嚥下が陰性に入る（下の「確かめていないこと」）。

### 3. 収集日の規則

- 学習側のどの日も、評価側のどの日より前（日付で `M4_EVAL_FROM` より前）。学習側の締め（10/28）と `M4_EVAL_FROM`（11/01）の間は空けてよい。
- `M4_EVAL_FROM` 以降に `pc-throat` のセッション（PC の経路の記録）を録らない。録ってしまったものは M4 に使わない（`data/raw/` に残す）。
- 装置の `meal` を `M4_EVAL_FROM` より前に録らない（#47 の動作確認は `water` など `meal` 以外で行う。`meal` の名前で録ったものは評価に使わない）。
- 収集日はフォルダ名の日付で数える（0014・0031。同じ日の複数の食事は 1 収集日）。

### 4. 評価用の `meal` は検出器だけで録る（D8 の (b)）

- 評価用の `meal` は装置（`tools/record.py --unoq-detector`、#47）だけで録る。生の音声は UNO Q にも PC にも残らない（CLAUDE.md「データの扱い」、0025・0035）。
- 0028 決定 3（記録の経路と検出器を同時に動かさない）はそのまま。学習用 `meal` の記録の間は `detector.py` を動かさない。評価用 `meal` の間は `arecord` を動かさない。
- 装置の出力と PC の再計算の一致は、評価側ではなく、**学習用 `meal` の `throat.wav` を `detector.py` の再生モード（#47。ファイルは読むが書かない）に流して**確かめる。
- **評価用の `meal` では FEAT を有効にする。** D7 の既定（窓ごとの結果だけ）の例外。
  - 根拠: 0005 の範囲内（特徴量に変換した後の値で、生の音声波形ではない）。M2 で #20 の FEAT を足した理由と同じく、届かなかった場合の原因の切り分け
    （咀嚼か会話か、嚥下の直後の延びか）に使う。`self` だけ。
  - **FEAT は窓ごとの要約の値だけ。CNN の入力（`mfe40` の 98 フレーム × 40 本の対数メル）をそのまま送らない。** フレーム単位（10 ms ごと）の
    時間周波数の行列は、食卓の会話（同席者の声を含む）の音に近いものを PC 側で組み立て直せるおそれがあるため。
  - 要約の値の方針（名前と次元の確定、`meta.json` の `feature_names` は #47）:
    - 1 窓（1.0 秒）に 1 行、0.25 秒ごと（DETECT と同じ窓）。値は窓の中の 98 フレームを時間方向に畳んだ統計量だけで、フレームごとの値を含めない。
    - 中身: `mfe40` と同じ前処理（16 kHz、0〜4000 Hz、メル 40 本の対数）の帯域ごとの窓内の平均 40（`mel_mean_00`〜`mel_mean_39`）と
      標準偏差 40（`mel_std_00`〜`mel_std_39`）、窓の対数エネルギーの平均と最大 2（`log_energy_mean`・`log_energy_max`）。計 82 次元。
    - 上限: 1 窓あたり 100 次元以下。窓より細かい時間の分解能を持つ値（フレームごとの値、デルタの系列、窓の一部だけの統計量）を入れない。
      フレームの系列を出さず、窓ごとに畳んで情報量を減らす。ただし FEAT から音を組み立て直せるか・内容（話の中身など）を推定できるかは
      確かめていない（下の「確かめていないこと」）。
    - 正規化の前の値（0021 の FEAT と同じ）。CNN の重み・中間層の出力は入れない。
  - FEAT は `data/raw/` の外に出さない・コミットしない（0021 と同じ。生の計測データとして扱う）。#49 の 1 回の採点の後に、原因の切り分けにだけ使う。
    FEAT を見た後に構成・閾値・後処理を変えない。

### 5. `s` の押し方、捨てる条件、打ち切り

- `s` の押し方は 0023 のまま（食べ物・飲み物を意識して飲み込んだときに押す。打ち忘れ・打ち遅れでは捨てない。体感の 3 段を集計表に書く）。学習用・評価用とも同じ。
- 区切り: 学習用・評価用とも `o start` から後が記録の範囲（0031）。会話ありは `o start` の後、食べ始める前に `o conv`（0023 と同じ綴り）。
- **捨てる条件（学習用 `meal`、PC の経路）**: `docs/recording-protocol.md`「咽喉マイク（M3）」の 1〜7・9・10 を当てる。ただし 5（止まり方）は
  `throat.stop` が `interrupt`（食べ終わって Ctrl-C）か `duration`（30 分の自動終了）なら使う（`stall`・`child-exit`・`error` は捨てる）。
  8（M1 の「捨てる」）は当てず、0023 の 6（終わりの 1.5 秒以内の `s`）・8（`conv` の綴り）・9（`s` に関わる `wrong key`）に置き換える。
  「他の人の声が入った」は捨てる理由にしない（会話ありは相手の声が入る）。
- **捨てる条件（評価用 `meal`、装置）**: 0023 の 1〜9 を装置の形に読み替える。
  1. 窓の取りこぼし（`window_t_ms` の飛び）が 1% 以上。
  2. （0023 の XOR の読み替え）`detector.py` の出力の行で読めないもの・形式の違うものが 1 行以上。
  3. `window_t_ms`・`t_ms` の逆行、隣との差が 1000 ms 超。
  4. 窓の終端から PC の受信までの遅れの最大が 1000 ms 超（0021 の上限。#47 が受信時刻を残す）。
  5. `o start` が無い・2 つ以上・最初の窓より前、`o start` より前に `s`・`t`・`c` がある。
  6. 終わりの 1.5 秒以内に `s` がある（30 分の自動終了を含む）。
  7. `meta.json` の `fw` が #47 で決める装置の値でない、構成（0038 の識別子）が 0038 と違う、FEAT が無効。
  8. 会話ありの `conv` の綴り違い。
  9. `s` に関わる `wrong key`。
  - 採否は `positive`・`prob`・`led`・FEAT の値を見ずに、人が記録の直後に決める（0023）。採否を確かめる道具は時刻の列だけを読む（#47・#48）。
- **打ち切り**: `M4_EVAL_TO` = 2026-11-04 の終わり（フォルダ名の日付が `20261104` 以前）。それより後に延ばさない。届かなくても延ばさない。
  - 3 セッション以上なら合算（M4 の数字）を出す。3 セッション未満なら合算と合格線との比較を出さず、セッションごとの数字を「M4 の合算は未達で出せない」と明記して出す（0023 と同じ）。
  - 打ち切りの後に録った `meal` は `data/raw/` に残して M4 に使わない。
  - 途中で装置の構成（0038）やプログラムを書き換えたら、それより前の評価用 `meal` は M4 の数字に使わない（0023 の「書き換え前」と同じ）。

## #47・#49 への申し送り（この記録ではコードを変えない）

- #47: 装置のセッション（`detect.csv` があり `fw` が `detector` でない）が `data/raw/` に入っても、`split.py`（M1・M3 の経路）が止まらないようにする
  （今は「検出器のファイルがあるのに fw が detector ではない」で止まる）。装置の `fw` の値、FEAT の次元と名前、受信時刻の列は #47 で `docs/data-schema.md` に書く。
- #49: 評価側の入口は、評価側のファイルを開く前に印 `docs/log/m4-final-49.txt` を排他作成し、その後の手順で止まっても印を消さない（0034:32 の 3b と同じ）。
- #49: `evaluate_detector.py` の `scan_root` は、`self` の `meal` で `fw` が `detector` でないもの（学習用 `meal`）があると止まる。M4 の入口は
  `M4-EVAL` の一覧で対象を決め、M2 の `meal`（`fw` = `detector`、10/2〜10/4）を拾わないようにする。

## 理由

- 学習に `meal` を入れる: M2 は条件別だけで学習して `meal` で 0.150 だった（0027）。食事の咀嚼・会話・食器の音は条件別の 7 本に無い。
- 学習用 `meal` 3 本: 2 本では条件別 21 本に対する比率が小さい（人の決定 10/13）。
- 日付の境で分ける: 評価側と学習側でセッションの種類が違い、「名前順で後ろから」では分けられない。日付の境は記録の前に決められ、性能の数字に依らない。
- 評価用を装置だけで録る: 評価の数字は装置の出力で出す（`docs/plan.md`「装置上の推論」）。検出器に音声の出口を作らない（CLAUDE.md、D8）。
- 打ち切りを日付で決める: M4 の締め（11/7）は動かない。陽性を見る前に日付だけで決める（0023 と同じ）。

## 選ばなかった案

- 評価側を `split.py` の「後ろから N 本」で決める: 装置のセッションと PC のセッションを同じ並びに入れることになり、M1・M3 の経路の検査と衝突する。
- 評価用 `meal` で生の音声も録る（(a) ALSA の分岐）: 0029 の「ALSA のユーザー設定が無いこと」と衝突し、検出器の取り込み口を 2 つにする（人の決定 10/13 で (b)）。
- M3 の評価側 7 本を M4 でも学習に使わない: 条件別の学習データが 14 本に減る。M3 は判定済みで、M4 の評価側とは別の日・別の種類。
- FEAT を出さない（D7 の既定のまま）: 届かなかったときの切り分けの材料が無くなる（人の決定 10/13）。
- 評価側をちょうど 2 収集日に限る（0014 の文字どおり）: 窓の中で 3 日目に録った採用分を外すことになり、セッションを選んだ形になる。
- 評価側を 1 収集日以上にする（0032 と同じ）: 評価側の中で収集日が分かれず、M2（3 収集日）と並べにくい。
- 日程を 10/30〜11/2 のままにする: 学習用の締めから #45 の 0038 と #47 の配置まで 1 日しかない。学習用 `meal` を 2 本に減らす: 10/13 の「2 本では比率が小さい」に反する。
- M3 の検査（`assert_fixed_eval_not_in`）を外す: M3 の数字を M4 のデータで出し直す経路が開く。
- FEAT に `mfe40` の 98 × 40 をそのまま入れる（PC で評価側の確率を計算し直せる）: 会話の音に近いものを組み立て直せるおそれがある。
  装置と PC の一致は学習用 `meal` の再生モードで確かめる。

## 確かめていないこと

- `meal` の `s` は押せた嚥下だけ（0023）。学習用 `meal` で押せなかった嚥下は陰性として学習に入る。#45 の hard negative（学習側 CV で誤検出になった区間の
  重み付け）は、押せなかった本物の嚥下を重く陰性と教えるおそれがある。向きと大きさは確かめていない（#45 で扱う）。
- 学習用 `meal`（PC の経路、`arecord`）と評価用 `meal`（装置、ALSA から `detector.py`）で、入力の利得・間引きが同じ値を出すか。再生モード（#47）は
  同じファイルからの計算の一致を見るだけで、取り込み口の違いは見ない。
- 学習側の日（10/11・10/12・学習用 `meal` の日）と評価側の日の差（装着・体調）の影響。
- 評価用の FEAT（窓ごとの要約の値、0.25 秒ごと、窓は 0.75 秒ずつ重なる）から、音を組み立て直せるか、会話の内容を推定できるか。
  フレームの系列を出さないことで情報量は減るが、組み立て直せないことは確かめていない。
