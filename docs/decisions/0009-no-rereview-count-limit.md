# 0009 再レビューの回数制限をなくす

日付: 2026-09-20　状態: 採用

## 決定

- 「再レビューは2回まで」（docs/decisions/0004、0008）をやめる。plan レビューにも関門のレビューにも、
  回数の上限を置かない。
- 止める条件は回数ではなく中身で決める。
  - ゲートは BLOCKING だけ、は変えない。BLOCKING が残っている間は、直して再レビューする。
  - CONCERN だけになったら、エージェントは自分の判断で回し続けない。採否を人に渡し、
    直して再レビューするか、そのまま進むかは人が決める。
  - 同じ指摘が2回続けて出た、または直すたびに隣の指摘が出て収束しないときは、その旨を添えて
    人に渡す。
- plan の再レビューは resume（docs/decisions/0008）。関門の再レビューは fresh のまま
  （`/codex:adversarial-review` に resume の機能が無い）。

## 理由

- 回数の上限は、fresh のレビューが毎回新しい CONCERN を出して終わらないことへの歯止めだった
  （#2）。plan の再レビューを resume にしたので、その理由は弱くなった。
- 一律に N 回で切ると、直せば済む指摘が残ったまま人に渡る。M0 の関門（#6）では、2回目の
  再レビューで出た指摘を、上限のために再レビューなしで人が判断することになった。
- 止めどころは BLOCKING の有無と人の採否で決まっており、回数を別に数える必要がない。

## 注意

- 関門の再レビューは fresh なので、#2 と同じこと（毎回、前の修正の隣に新しい指摘が出る）が起きうる。
  #6 では3回とも1件ずつ出た（`--out` → `cond` → `data/raw` のリンク）。上の「収束しないときは人に渡す」は
  このための条件。
