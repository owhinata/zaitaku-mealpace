# 0051 ProtoPedia のストーリー本文は割合と 1 分あたりの回数だけを書き、混同行列とセッション一覧は本文に置かない

日付: 2026-11-05　状態: 人の決定を記録（2026-11-05、Issue #56、PR #60 でのチャットの指示）。CLAUDE.md「評価」の書き換えは人

Issue #56 のストーリー本文（`docs/protopedia/story.1.md`。ProtoPedia の作品ページの「ストーリー」欄に貼る文章）の、評価の数字の書き方を決める。
`docs/evaluation.md` の定義（窓、イベント単位の数え方、分割、合格線）は変えていない。0042 の数字も変えていない。

## 背景

- CLAUDE.md「評価」: 「85%達成」のような報告には、混同行列と評価に使ったセッション一覧を必ず添える。`docs/evaluation.md`「分割」にも
  「報告には、評価に使ったセッションの一覧と混同行列を必ず添える」とある。Issue #56 の完了の条件も、本文に混同行列とセッション一覧を求めていた。
- ストーリー本文の読者は介助者を含む一般の人。人の指摘（11/4・11/5）: 細かい結果レポートは要らない。混同行列は要らない。「検出率 0.957」は
  何の割合かが分からない。「208 回のうち」「56 分のあいだ」のような内訳、食事の回数、開発記録へのリンクの一文も要らない。
- メインは 11/5 に、数とリンクを本文から外すと CLAUDE.md「評価」の決まりの外に出ることを伝えた。人はそのうえで外すと決めた。

## 決定（人の決定 2026-11-05）

1. **ストーリー本文の評価の数字は、割合と 1 分あたりの回数だけを書く。** 「人が判断した飲み込みのうち、装置が検出できた割合 95.7%」
   「飲み込んでいないときに、装置が検出を出した回数 1 分あたり 1.25 回」と、目標（85% 以上、1 分あたり 1 回以下）、目標との比較（満たす / 満たさない）。
   最初の構成（M2）との比較は表にし、同じ 2 つの数字（15.0%、1 分あたり 2.03 回）を並べる。
2. **混同行列（TP 199 / FN 9 / FP 70）、分母と分子（199/208、70 回 / 56.00 分）、評価に使ったセッション一覧、開発記録へのリンクの一文は、
   ストーリー本文に置かない。** これは CLAUDE.md「評価」と `docs/evaluation.md`「分割」の「必ず添える」の、ストーリー本文に限った例外。
3. **混同行列とセッション一覧の置き場は 0042（と 0041 の追記、docs/log/2026-11-01.md）のまま。** 作品ページの関連リンクにリポジトリの URL を
   書く（人の作業。ProtoPedia の別の項目）ので、数字の裏づけはそこから辿れる。
4. **例外はストーリー本文だけ。** README、`docs/`、Issue、log、関門の判定の記録など、ほかの報告には今までどおり混同行列とセッション一覧を添える。
5. **変えない表現の決まり。** 「達成」と書かない、「約」で丸めない、目標との比較は「満たす / 満たさない」、LED は「目安」（CLAUDE.md「表現」、
   Issue #56 の完了の条件）。本文の 95.7% は 199/208、15.0% は 21/140 を小数 1 桁で書いたもの（0042・0027 の 0.957・0.150 と同じ値）。
6. CLAUDE.md「評価」の 3 行目は、この記録の後に人が書き換える（CLAUDE.md の冒頭の決まり）。書き換えるまでは、この記録で読み替える。
   案: 「「85%達成」のような報告には、混同行列と評価に使ったセッション一覧を必ず添える（ProtoPedia のストーリー本文は docs/decisions/0051 の例外）。」

## 同じ日の関連する人の決定（Issue #56 の構成と完了の条件の読み替え）

- 7 段の構成にこだわらない。「介助者が、その場で確かめられること」「目指しているのは、いつもの食卓で使える道具」「小さな光が、介助の手がかりになる未来へ」
  「開発とデモについて」の節は置かない（使用技術・リポジトリ・動画は ProtoPedia の別の項目にある）。
- 既存製品（GOKURI・B4S）との位置づけは本文に置かない。完了の条件の「既存製品に関する記述に調査日」は、記述が無いので当たらない。
- 誤検出の原因の推測（会話・食器の音・マイクへの接触）と、M2 と M4 の差の原因を絞れないという注記は本文に置かない。
- 冒頭に服薬の場面を入れた。評価は食事だけで、服薬の場面は未検証の一覧に書く。

## 代償（外したことで守れなくなるもの）

- ストーリー本文だけを読む人は、95.7% の分母（208 回）と、誤検出の回数の基になった時間（56.00 分）、評価に使った食事の本数と日付を知ることができない。
  数字の重みを読者が自分で確かめるには、リポジトリの 0042 まで辿る必要がある。
- 本文に原因の切り分けが無いので、「届かなかった数字と原因の切り分けを公開の材料にする」（`docs/plan.md` の M4 の行）のうち、
  作品ページに出るのは届かなかった数字だけになる。切り分けは 0042 にある。
- 記事の文言は #59 の関門のレビューの focus。レビューでこの例外が指摘されたときは、この記録を採否の根拠にする。
