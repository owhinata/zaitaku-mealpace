## 決定

### 記録の側（手順の根拠）

| 項目 | 決定 | 誰が |
|---|---|---|
| 1 セッションの長さ | 210 秒（`--duration 210`）。叩き・装着・`o start` の分 約 30 秒 + 条件 約 180 秒 | 人 |
| 叩き | 毎セッションの冒頭に 5 回（Enter をマイクのケースで押す）。セッションごとに外して付け直す | メイン |
| 叩きの `Δ` | 叩きが 3 回未満、または `\|Δ の中央値\|` > 125 ms → 使わない（録り直す）。3 回以上かつ 50 ms < `\|Δ の中央値\|` ≤ 125 ms → 印を付けたまま使う。`Δ` で時刻の対応を直さない | 人 |
| バンド | SH-12JK の付属のバンド（`--band sh12jk-strap`） | 人 |
| 装着の側 | 最初の収集日に人が決め、その日の log に書く。全収集日で同じ側。`--position lateral-below-cricoid` は変えない | 人 |
| 収集日 | 4 収集日を 2026-10-18 までに（Issue の完了の条件は 3 収集日以上） | 人 |
| 評価側 | 最後の 2 収集日のセッション全部（M1 と同じ規則。0014 の `EVAL_DAYS` = 2）。学習はそれより前の収集日の全部 | 人 |
| 記録の範囲の始まり | `o start`（装着して落ち着いてから打つ）。下の「記録の範囲」 | 人 |

理由:

- **210 秒**: 叩きを込みで 180 秒にすると条件の時間が約 150 秒に減り、M1 の 1 日あたりの量（嚥下 約 25 回、`t`+`c`+`n` 約 40 回、`quiet` 3 分）と比べられない。
  叩きの分を足して、`o start` から後を M1 と同じ約 180 秒にする（1 収集日 24.5 分）。
- **毎セッションの叩きと付け直し**: 各セッションの時刻の対応（受信の時刻による対応。0029）を、そのセッションの叩きで確かめるため。叩きでマイクを手に持つので、
  付け直しが要る。M1 の「同じ日のセッションの間は外さない」は咽喉マイクには当てない。
- **125 ms**: `arecord` の 1 ピリオド（`throat_check.PERIOD_MS`）で、評価の区間 `[t − 0.5 s, t + 1.5 s]` の幅 2.0 秒に比べて小さい。#37 の有線の 5 本は
  −55〜−74 ms で、50 ms の印が付いたまま人が判定に使った（docs/log/2026-10-10.md「人の判定」）。`throat_check.py` の 50 ms の印の表示は変えない。
- **代替の叩き（`--tap-mode finger`）は使わない**: `Δ` が出ず、上の規則を当てられない。#37 では Enter の叩きが 5 本とも 5 / 5 見つかった。

### 記録の範囲の始まり = `o start`（0011「記録の範囲」の読み替え）

- 咽喉マイクのセッション（`fw` = `pc-throat`）の記録の範囲は、**始まり = `o start`（note が `start` の `o`）の `t_ms`、終わり = 最後のサンプルの時刻**
  （`throat_chunks.csv` から 0029 の受信の時刻による対応で出す `τ(N)`。N は 48 kHz のフレーム数）。
- `o start` が無い・2 つ以上ある、始まりが終わり以降のセッションはエラーにする。`throat_chunks.csv` の `t_ms` の逆行・1 秒を超える飛びは 0011 と同じくエラー。
  範囲の外の `s` は 0011 のままエラー。記録の手順では `o start` より前に `s`・`t`・`c`・`n`・`q` があるセッションを捨てる。
- 理由: 手に持ったマイクの叩きと装着の音は、使う場面に無い大きな音で、誤検出率の分母（非嚥下区間の分数）と分子（誤検出の回数）を記録の作法で動かす。
  M1 の記録にはこの区間が無かった。外すのは範囲の始まりだけで、窓・数え方・非嚥下区間の定義は変えない。
- 選ばなかった案: **叩き込みで記録の全体を範囲にする**（0011 をそのまま当てる）。叩き・装着の音が誤検出に入り、M1 と比べられない。

### 既存の評価器との接続の方針（0025 の 4。実装は段 B）

- 咽喉マイクのセッションは**咽喉マイクのセッションだけで**分割・学習・評価する。M1 の Nano のセッション（28 本）、M2 の `meal`（検出器）と混ぜない。
- 特徴量は 0012 の音の 15 次元（MFCC 13・スペクトル重心・ゼロ交差率）の式のまま、IMU なし（0026）。M2 の 0020 の式は使わない。
  `throat.wav` の L（ch0）を `scipy.signal.resample_poly(x, 1, 3)` で 16 kHz に落とす（0029）。
- サンプルの時刻は `tools/throat_check.py` の `sample_time_map`（受信の時刻による対応。0029）。叩きの `Δ` で直さない。
- 学習と閾値の手順は 0014 のまま（ロジスティック回帰、`C=1.0`、`balanced`、閾値の格子、収集日ごとの交差検証、誤検出 3.0 回/分以下で検出率が最大）。
  評価側（最後の 2 収集日）の扱い（既定の実行で評価側を開かない、`--final`、報告に混同行列とセッション一覧）も 0014 のまま。
- `analysis/split.py` は、`data/raw/` の直下で名前がちょうど `trial-throat` のディレクトリ（試用の置き場、#37）だけを読まずに飛ばす。他の形式に合わない名前は今までどおり止まる。
  M1 の分割に咽喉マイクのセッションが混ざらないようにする（今のコードは `fw` が `detector` でないものを全部 M1 の分割に入れる）。
- 選ばなかった案:
  - **M1 の 28 本と合わせて学習する。** 別のマイク・別の装着で、0026「引き継ぐ範囲」に合わない。
  - **読めるファイルの形（16 kHz の `audio.wav` など）に変換して保存する。** 生の音声の複製が `data/raw/` に増え、落とし方が記録の時点で固定される。
  - **叩きの `Δ` で対応を直す。** 0029 で選ばなかった（叩きが見つからない記録で対応が出せない）。

## 確かめていないこと

- 210 秒で叩き・装着・`o start` が 30 秒に収まるか（見込み）。収まらなければ条件の時間が 180 秒より短くなるだけで、採否には使わない。
- 180 秒を超える連続受信（210 秒）での overrun（180 秒までは 0。0028）。
- セッションごとの付け直しで、同じ日の中の装着のばらつきがどれだけ出るか。
- 叩きの `Δ`（−55〜−74 ms）の原因（鍵盤から `record.py` までの遅れと見られる）。
