## 決定

1. **M4 の判定に使う構成**（25 行のうち、報告の規則の次点の行。人の決定 10/29）:
   - 分類器: **CNN**（`mfe40`、0033 §2 の構成と学習のまま）を種 0・1・2 で学習し、窓ごとの確率（シグモイドの出力）の算術平均を取る（plan #45 の 5.2。C4）。hard negative は使わない。
   - **分類器は CNN（LR ではない）。** 0039 決定 5 の入力: 装置（UNO Q の Linux 側）は 1 窓に CNN を 3 回回す。ランタイムの採否は 0039 決定 5 のとおり別の decision で決める（この記録では決めない）。
   - 後処理: ヒステリシス 入り 0.85・出 0.65 → 不応期 0.5 秒（塊ごと抑える）。塊の上限は使わない（`postprocess.PostStepper`・`post_mask`。plan #45 の 5.4。P2）。
   - 窓・ホップ（0.25 秒）・ラベル・数え方は変えない。LED は後処理の出力から 0018 の規則で決まる「目安」で、嚥下の有無の検出を示すだけ。

   25 行の中ではその動作点の誤検出率が 1.0 回/分以下の行で検出率が最大（同率なら単純なほう）。比べる数字は学習側 26 本の合算だけ。この規則が選んだ行は
   **C4 × P4**（入り 0.80・出 0.50・上限 1.5 秒・不応期 0.5 秒。検出率 0.960、誤検出率 0.99 回/分）だった。

   規則では選択に使わないと決めていた数字）。(c) 規則を「検出率が合格線以上の行で誤検出率が最小」としていれば P2 が選ばれた。規則の向き（誤検出を制約、検出率を目的）は

## 確かめていないこと

- 学習側 CV は楽観側で、規則からの変更でさらに楽観側。評価側で合格線（85% / 1.0 回/分）を満たすかは分からない。
- 評価側は `meal` だけ。学習側 CV の `meal` だけの誤検出率は 1.25 回/分で 1.0 を上回る（25 行のどの行も `meal` だけでは 1.0 を上回り、1.25 がその最小）。
  評価側の誤検出率が合算（0.86）より `meal` だけの値に近く出るおそれがある。
- 誤検出の中身の表は R0 と規則が選んだ P4 の行だけで、P2 の行の内訳は出していない（P4 の内訳では `meal` の会話あり・なしの区間が 97 / 144 回、嚥下の直前 18・直後の延び 8）。
- 常時陽性の誤検出率（0.18 回/分）は合格線の上限を下回る（0011「既知の弱点」。セッションごとに塊が 1 つで、`meal` の非嚥下の分数が長いためと見る。推測）。採用した行の陽性窓の割合は 0.050 で、常時陽性に近い出し方ではない。
- 学習側 CV（収集日ごと）で選んだ動作点が、評価側（別の日、装置の取り込み口）に移るか（0032・0037「確かめていないこと」と同じ）。
- UNO Q で CNN を 1 窓 3 回回す時間（#44・#51 の数字からの見込みは 1 窓 100 ms 前後（推測、plan #45 の 5.2）。実測は #47）。
- 押せなかった本物の嚥下が `meal` では陰性として学習・採点に入る（0023・0037）。採用した行は hard negative を使わないので、重く陰性と教えることはない。
