### あわせて決めること: M4 の 2 週間で削るもの（0024「確かめていないこと」、#41 の本文）

0024 で「M4 の 2 週間で収集・学習・装置上の推論・`meal` が収まるか」は確かめておらず、削る候補のどれにするかは M3 の判定のときに決めるとした。
候補は次の 2 つ（どちらも削らない、両方削る、も人の選択肢）。

- **装置上の推論を PC 上の推論に置き換えて公開し、装置化は応募後にする。**
- **`meal` の本数を減らす。**

関係する事実:

- UNO Q の Linux 側での推論時間は測っていない（CNN・特徴量とも。M4 で測る。人の決定 D7、0035）。PC では CNN 1 窓 1.05 ms、`mfe40` の特徴量 1 窓 0.23 ms（中央値。docs/log/2026-10-12.md）。
- UNO Q の上に numpy は無い（0035）。librosa を入れるか・動くかは M4 の設計と一緒に決める（0035 D7、0033）。
- Linux 側から MCU への RPC の往復は中央値 約 5.1〜5.3 ms（0035 の表。検出器を動かしていないときの値）。LED マトリクスの状態 0 / 1 / 2 の表示は動く（表示の規則（0018）は M4）。
- PD 給電（モバイルバッテリー → CM721 の PD パススルー → UNO Q）で起動・USB オーディオ・RPC・60 秒の記録に問題は無かった（0035）。
  持ち時間は待機だけで 6.8 %/時（満充電からの上限の概算 14〜15 時間）。推論を回しながらの値は M4。
- 装置と PC の推論コードは同じ Python にする方針（0025）。0012・0014 の手順は PC で動いている。
