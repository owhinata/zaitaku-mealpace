# 0012 窓ごとの特徴量の式を、実データを見る前に固定する

日付: 2026-09-20　状態: 採用

`docs/evaluation.md` の定義と合格線は変えていない。`docs/data-schema.md` も変えていない。
`docs/evaluation.md` は窓（1.0 秒 / 0.25 秒）と特徴量の名前（IMU: 振幅、RMS、ピーク数、主軸方向。音: MFCC 13 次元、
スペクトル重心、ゼロ交差率）を決めているが、式は決めていない。式をここに固定し、`analysis/features.py` に実装した（#11）。
式・定数・閾値は人が決めた。採否の経緯は Issue #11 のコメントにある。

## 決定

### 特徴量（計 29 次元。`FEATURE_NAMES` の順）

前処理: 加速度 3 軸とジャイロ 3 軸は、それぞれ窓内の平均を引く。フィルタは掛けない。

| 名前 | 定義 | 次元 |
|---|---|---|
| 振幅 | 加速度の各軸の peak-to-peak（3）と、ジャイロのノルムの peak-to-peak（1） | 4 |
| RMS | 加速度の各軸（3）と、ジャイロの各軸（3） | 6 |
| ピーク数 | 加速度のノルムの局所極大の数。高さが窓内の RMS × 1.0 以上、最小間隔 50 ms（近いものは高いほうを残す） | 1 |
| 主軸方向 | 加速度の 3×3 共分散行列の第1固有ベクトル（単位ベクトル）。符号は、`|Y|` が 1e-6 以上なら Y 成分を正に、そうでなければ X、次に Z の順で最初の `|成分|` ≥ 1e-6 を正にそろえる。第1固有値 λ1 が 1e-8 g² 未満（静止）のとき、または `λ1 − λ2 < 0.01 × λ1`（固有値がほぼ重なり、主軸が一意に決まらない）のときは `[0, 1, 0]` | 3 |
| MFCC | フレーム 25 ms（400 サンプル）/ 10 ms（160）、Hamming、プリエンファシス 0.97、`n_fft` 512、メル 26 本（0〜8000 Hz、HTK 式）、`log(E + 1e-10)`、DCT-II（ortho）の先頭 13 係数（c0 を含む）。窓内の 98 フレームの平均 | 13 |
| スペクトル重心 | フレームごとの `Σ f·P / Σ P`（Hz、プリエンファシス前）の窓内平均。`Σ P` がほぼ 0 のフレームは 0 | 1 |
| ゼロ交差率 | 窓内の平均を引いた波形の符号の変化回数 ÷ (N − 1) | 1 |

- 音声は int16 を 32768 で割った float32。読み込みは標準ライブラリの `wave`。
- 主軸の既定値 `[0, 1, 0]` は装着の向き（Y 軸が首の上下方向、+Y が頭側。`docs/data-schema.md`）に合わせた。符号を Y から
  そろえるのも同じ理由。固有ベクトルは符号が決まらないので、そろえないと同じ動きが窓ごとに反対向きの値になる。
  固有値がほぼ重なるときは向きが数値誤差で決まるので、既定値にする。

上の表が決めていない細部は、実装時に次のとおりにした（同じく #13 の結果を見てから動かさない）。

- 分散・共分散・RMS、`Standardizer` の標準偏差は ÷ n。
- ピーク数の局所極大は `x[i] > x[i−1]` かつ `x[i] ≥ x[i+1]`（窓の両端は数えない）。高さの基準の RMS は、平均を引いた
  加速度のノルムの窓内 RMS。最小間隔は行数ではなく `t_ms` の差で測る。
- パワースペクトルは `|FFT|² ÷ n_fft`。メルの三角フィルタは FFT のビンの周波数で評価し、面積の正規化はしない。
- スペクトル重心のフレームは MFCC と同じ切り方（400 / 160、Hamming）。`Σ P < 1e-12` のフレームは 0。
- ゼロ交差率の符号は `x − 平均 ≥ 0` を正とする。
- 特徴量の名前は `acc_ptp_{x,y,z}`、`gyro_norm_ptp`、`acc_rms_{x,y,z}`、`gyro_rms_{x,y,z}`、`acc_peak_count`、
  `acc_axis_{x,y,z}`、`mfcc_0`〜`mfcc_12`、`spectral_centroid_hz`、`zero_crossing_rate`。

### 窓と時刻

- 時間軸は装置の `t_ms` ÷ 1000（秒）。0 への付け替えはしない（`analysis/evaluate.py` の `load_events` と同じ軸）。
  `WINDOW_S` / `HOP_S` は `analysis/evaluate.py` から import し、二重に定義しない。
- 音声サンプルの時刻は `audio_chunks.csv` の `(sample_index, t_ms)` をアンカーにして出す。チャンクの間は線形補間、
  最後のアンカー以後は 16 kHz の傾きで WAV の最後のサンプルまで補外する。チャンク長は `sample_index` の差分の最頻値。
  チャンクの `t_ms` は「先頭サンプルの時刻」として扱う（`docs/data-schema.md`）。実装が末尾付近の時刻を刻んでいる疑い
  （#15、最大 4 ms）は、定数 `AUDIO_CHUNK_T_OFFSET_MS = 0.0`（`t_ms` に足す ms）の1か所に置き、#15 の結論で変える。
- 各ストリームの範囲は半開区間。音声は `[先頭サンプルの時刻, 最終サンプルの直後の時刻)`、IMU は
  `[最初の行の t_ms, 最後の行の t_ms + 1周期)`。`t_lo` は開始の大きいほう、`t_hi` は排他的な終端の小さいほう。
  窓 k は `[t_lo + 0.25 k, t_lo + 0.25 k + 1.0)`、窓の数は `floor((t_hi − t_lo − 1.0) / 0.25 + 1e-9) + 1`。
- IMU は `t_ms` で窓に入る行を選ぶ。音声は窓の開始時刻に最も近いサンプルから 16000 サンプル固定。
- 入力の検証（合わなければ `ValueError`）: `audio.wav` が mono・int16・16000 Hz（`meta.json` のトップレベル `audio_hz`
  を優先し、無ければ `sample_rates.audio_hz`。0006。WAV のヘッダーとも一致）、`audio_chunks.csv` が 2 行以上・最初の
  `sample_index` が 0・`sample_index` が狭義の単調増加・`t_ms` が単調非減少、最終チャンクの長さが 1 以上チャンク長以下、
  `imu.csv` が 2 行以上で `t_ms` が単調非減少。

### 無効な窓

- 取りこぼしの基準は `tools/check_session.py` と同じ（`GAP_RATIO = 1.5`）。IMU の1周期は、飛びでない `t_ms` の差分
  （中央値の 1.5 倍未満）の平均。音声の1周期はチャンク長 ÷ 16000。差分が 1.5 周期以上の箇所を飛びとする。
- 飛びの区間 `(前の時刻, 次の時刻)` と `[開始, 開始 + 1.0)` が交わる窓、IMU の行数が期待（1.0 ÷ 周期）の 90% 未満の窓は
  `valid = False`。音声が 16000 サンプルに満たない窓も `valid = False`（0 で埋めた次元を、有効な窓として学習に
  渡さないため。実装時に足した）。
- 窓は落とさず、グリッドは等間隔のまま返す（`evaluate.py` の連続の判定を壊さない）。
- 無効な窓でも `X` は有限値を返す。窓に入ったサンプルで計算し、計算できない次元は 0 にする（IMU が 2 行未満なら、
  主軸も含めて IMU の 14 次元。音声が 16000 サンプルに満たなければ音の 15 次元）。NaN / inf を返さない。
- 無効な窓を学習と正規化から外すこと、評価での扱いは #13 で決める。

### 正規化と API

- `extract_session` は常に正規化前の値を返す。モジュールの中に、全データを走査して統計量を作る経路を置かない。
- `Standardizer.fit` は、呼び出し側が渡したセッションの `valid` な窓だけから統計量を作り、使ったセッション名
  （有効な窓が1つ以上あったもの）を `sessions` に残す。#13 の報告で、評価側が混ざっていないことを確かめられる。
  `std` が 0 の次元は 1 にする。
- 窓へのラベル付け（どの窓を嚥下の窓として学習するか）は #13 で決める。#11 には入れていない。

## 理由

- **実データを見る前に固定する。** M1 の分岐点の数字（#13）はこの特徴量から出る。式・定数・閾値を先に決めておけば、
  結果を見てから特徴量を動かす余地が残らない（0003、0011 と同じ理由）。#13 の結果を見てからこの式を動かさない。
  動かす必要が出たら、ここに新しい記録を足してから変える。
- **加速度とジャイロの両方で窓内の平均を引く。** IMU のキャリブレーションを前提にしない。加速度の平均は重力と姿勢、
  ジャイロの平均はゼロ点のずれで、どちらも嚥下の動きではない。ジャイロのゼロ点のずれをそのままにすると RMS に入り、
  日や温度で動く値が特徴量に混ざる。窓内の平均を引けば、装置ごと・日ごとの補正値を持たずに済む。
- **依存は numpy だけ。** 式が手元のコードに全部書いてあれば、ライブラリの版や既定値（メルの式、フィルタの正規化、
  DCT の種類など）で値が変わらない。scipy・librosa は足さない。
- **特徴量を保存しない。** 60 秒のセッションの計算は 1 秒未満で済むので、その場で計算し直せる。ファイルに書く機能を
  置くと、`p1` の特徴量が出力先からコミットに紛れる経路ができる。戻り値にも生の波形と IMU の系列は含めない。
- **無効な窓を落とさない。** `evaluate.py` は陽性窓の間隔で連続を判定するので、窓を間引くとグリッドが崩れる。
  目印（`valid`）だけを付けて、扱いは使う側（#13）で決める。

## M2 との関係

この 29 次元は M1 の PC 側の評価用の定義。M2 で装置（FPU なし）に同じ実装を載せることは保証しない。98 フレームの
FFT を 250 ms ごとに計算し直すのは重い見込み（推測。docs/log/2026-09-20.md）。M2 で採るなら、重なる音声フレームの
再利用と実機での計測を先に行う。

## テスト

`analysis/test_features.py` の合成セッション（一時フォルダ。`data/` は使わない）で、窓の数と時刻、各特徴量の値、
取りこぼしの扱い、`Standardizer`、入力の検証を固定する。

- 合成の IMU は周期 9.48 ms を整数に丸めた `t_ms`（差分に 9 と 10 が混ざる）。
- 「同じ分散で無相関なら主軸は既定値」のケースは、IMU を 10 ms ちょうどの周期にして、X に `A sin`、Y に `A cos`（5 Hz）を
  入れる。どの窓にも整数周期（100 行）が入り、`(λ1 − λ2) / λ1` は 0.003 未満。9.48 ms の周期では窓の行数が 105 か 106 で
  端数が残り、同じ信号の比が 0.008〜0.011 と閾値 0.01 の境目に来るので、判定の確認に使えない。式と閾値は変えていない。
  境目の反対側（Y の振幅を 0.8 倍、比 約 0.36）で、既定値にならず固有ベクトル（X 軸）が返ることも確かめる。
