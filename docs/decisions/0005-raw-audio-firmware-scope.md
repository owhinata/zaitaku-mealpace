# 0005 生の音声波形の扱いを記録ファームウェアと検出器ファームウェアで分ける

日付: 2026-09-19　状態: 採用

## 決定

- 記録ファームウェア（`firmware/logger/`）は開発用の計測器であり、生の音声を PC に送ってよい。
- 検出器ファームウェア（M2 以降、食卓で使う形態）は、生の音声波形を保存も送信もしない。
  特徴量に変換した後に破棄する。
- PC 側の生波形は被験者ごとの規則に従う。`self` は制限なし。`p1` は暗号化ディスクのみに置き、
  モデル確定後に削除する。
- M3 の本人試用は記録ファームウェアで行う。本人が日常で使う段階では検出器ファームウェアに切り替える。

## 理由

- CLAUDE.md は「装置は生の音声波形を保存しない。特徴量に変換した後に破棄する」と定める一方、
  `docs/data-schema.md` の記録形式は、記録ファームウェアが音声をシリアルで PC に送り、
  PC が `data/raw/` に `audio.wav` を書く前提になっている。この2つの関係がどこにも書かれておらず、
  「生の音声波形を保存しない」を文字どおり読むと記録ファームウェア自体が違反に見えてしまっていた。
- 記録ファームウェアと検出器ファームウェアは目的が違う。前者は開発用の計測器で、学習データを
  取るために波形そのものが要る。後者は食卓で使う完成形で、波形を残す必要がない。食卓の会話を
  録音・保存しない（企画書 5章）という約束は、後者が波形を保存も送信もしないことで守る。
  この決定は、どちらの話をしているかをファームウェアの種類で分け、CLAUDE.md と
  `docs/data-schema.md` を両立させる。
